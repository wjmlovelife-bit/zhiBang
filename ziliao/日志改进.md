## 三、剩余缺口（按严重度）

### 🔴 P0-1：`stats.service.ts` 完全无 PinoLogger

- **位置**：`backend/src/modules/stats/stats.service.ts`
- **现状**：grep `logger|Logger|console` 0 匹配——**唯一漏网 service**
- **为什么是 P0**：
  - 销售汇总是核心业务接口
  - 其他 12 个 service 都已注入，唯一漏这一个破坏一致性
  - 出错无日志 → 排障只能本地复现
- **修改**：
  ```ts
  constructor(@InjectPinoLogger(StatsService.name) private readonly logger: PinoLogger) {}
  ```
  + XLSX 导出 / 聚合查询处加 `this.logger.info({ userId, dateFrom, dateTo }, 'salesSummary start')`

---

### 🟠 P1-1：`app.set('trust proxy', 1)` 未配置（**IP 审计失效**）

- **位置**：`backend/src/main.ts`（缺）
- **现状**：`auth.controller.ts:21` 用 `req.ip` 拿客户端 IP
- **后果**：
  - 部署在 cloudflared / nginx 反代后，`req.ip` 永远是 `127.0.0.1` 或代理 IP
  - `SysLoginLog.ip` 字段审计**完全失效**
- **修改**：
  ```ts
  app.set('trust proxy', 1);  // 信任 1 层反代
  // 或精确：app.set('trust proxy', 'loopback, linklocal, uniquelocal');
  ```

---

### 🟠 P1-2：`@IpAddress()` / `@UserAgent()` 装饰器未建

- **位置**：`backend/src/common/decorators/`（当前只有 current-user / oper-log / permissions / public 4 个）
- **现状**：
  - `auth.controller.ts:21-22` 直接 `req.ip` / `req.headers['user-agent']`
  - 其他 controller 想记录 IP/UA 只能 copy-paste
  - service 层 `requestContext.getCurrent()` **拿不到 IP/UA**
- **修改**：
  ```ts
  // common/decorators/ip.decorator.ts
  export const IpAddress = createParamDecorator((_, ctx) => {
    const req = ctx.switchToHttp().getRequest();
    return (req.ip || req.socket?.remoteAddress || '').toString();
  });

  // common/decorators/user-agent.decorator.ts
  export const UserAgent = createParamDecorator((_, ctx) => {
    const req = ctx.switchToHttp().getRequest();
    return (req.headers['user-agent'] || '').toString().slice(0, 500);
  });
  ```
- **同步**：`requestContext` 加 `ip` / `userAgent` 字段 + guard 里 patch

---

### 🟡 P2-1：`/api/frontend-log` 后端接收端缺防护

- **位置**：`backend/src/modules/frontend-log/frontend-log.controller.ts`
- **现状**：
  - 前端 `report.ts:22` 用 `sendBeacon` 上报
  - 后端接收端未做限流 / 脱敏：
    - 脚本可刷爆日志库
    - 上报 payload 可能含 URL token / 错误堆栈含敏感数据
- **修改**：
  - 加 `@nestjs/throttler` 限流（如 30 req/min/IP）
  - 接收时**白名单字段**（只保留 message / stack / url / ua / timestamp，丢弃其他）
  - `stack` 截断前 1KB

---

### 🟡 P2-2：`LoggingExceptionFilter` 4xx 全 warn 写盘可能撑爆日志

- **位置**：`backend/src/common/filters/logging-exception.filter.ts:50-52`
- **现状**：
  - 所有 4xx（401 / 403 / 404 / 429）都 warn 写盘
  - 高频 401（脚本扫描、爬虫）会**刷爆日志库**
- **修改建议**：
  ```ts
  if (status === 401) return;  // 401 不写盘（前端 axios 已处理）
  // 403 越权保留 warn（审计需要）
  // 404 / 400 降级为 debug（仅 dev 打）
  ```

3. **P2-1 throttler 选 storage**——单实例用内存，多实例要 Redis（否则限流失效）
4. **现有 backendTest 482 用例 + frontendTest 140 用例** —— P1-2 / P2-2 改动要跑全量回归
5. **日志文件大小** —— 开启 Prisma query + Interceptor 后日志量增加，注意 `pino-roll` 配置（当前 7 天保留够用）
6. **requestContext ALS 兼容性** —— Node 22 下 V8 已优化，但建议在 `catchError` 兜底分支打 `reqId` 验证不丢失
