# 智邦 CRM 数据备份方案

> **目的**：每晚 00:00 自动备份 zhibang 系统的 PostgreSQL 数据库 + 附件文件到独立目录，支持回溯恢复
> **备份目标目录**：`D:\github\xiangmutest\opencode\zhibangDataBackup`
> **制定日期**：2026-09-03

---

## 1. 备份内容

| 项 | 来源 | 大小 | 方法 | 增量 |
|---|---|---|---|---|
| **数据库** | `zhibang` 库（37 个表，~12 MB）| dump 后 gzip ~3 MB/天 | `pg_dump -Fc` + `gzip` | 全量 dump（数据小，每天全量无影响） |
| **uploads 附件** | `D:\github\xiangmutest\opencode\zhibang\backend\uploads\`（144 个文件，197 MB）| 增量 0-10 MB/天 | `robocopy /E` | **完美增量**（只复制新增/修改） |
| **备份日志** | 3 个 .bat 输出 | < 10 KB/天 | `.log` 文件 | — |

## 2. 保留策略

| 项 | 保留天数 | 保留方式 | 自动清理 |
|---|---|---|---|
| 数据库 dump | **7 天** | 每天 1 个文件，7 天前自动删 | `forfiles /d -7` |
| uploads 附件 | **只增不减** | `robocopy /E`（不删目标端文件），累积所有历史 | **不清理**（接受累积） |
| 备份日志 | **7 天** | 每天 1 个 .log，7 天前自动删 | `forfiles /d -7` |

## 4. 脚本实现

### 4.1 `backup-db.bat`（数据库备份）

```bat
@echo off
chcp 65001 > nul
title zhibang DB Backup

set BACKUP_DIR=D:\github\xiangmutest\opencode\zhibangDataBackup
set DATE=%date:~0,4%-%date:~5,2%-%date:~8,2%
set LOG_FILE=%BACKUP_DIR%\logs\%DATE%.log
set PG_BIN=D:\OdooPG\bin
set PG_USER=postgres
set PG_DBNAME=zhibang

echo ===================================== >> "%LOG_FILE%"
echo [DB Backup] %date% %time% 开始 >> "%LOG_FILE%"
echo ===================================== >> "%LOG_FILE%"

:: 1. dump
"%PG_BIN%\pg_dump.exe" -U %PG_USER% -Fc -d %PG_DBNAME% -f "%BACKUP_DIR%\db\%DATE%.dump" 2>> "%LOG_FILE%"
if %errorlevel% neq 0 (
    echo [DB Backup] ❌ pg_dump 失败 >> "%LOG_FILE%"
    exit /b 1
)

:: 2. gzip 压缩
gzip -f "%BACKUP_DIR%\db\%DATE%.dump" 2>> "%LOG_FILE%"
echo [DB Backup] ✅ 压缩完成: %DATE%.dump.gz >> "%LOG_FILE%"

:: 3. 清理 7 天前的 dump
forfiles /p "%BACKUP_DIR%\db" /m "*.dump.gz" /d -7 /c "cmd /c del @path" 2>> "%LOG_FILE%"

echo [DB Backup] 完成 %time% >> "%LOG_FILE%"
echo. >> "%LOG_FILE%"
```

### 4.2 `backup-uploads.bat`（附件备份）

```bat
@echo off
chcp 65001 > nul
title zhibang Uploads Backup

set BACKUP_DIR=D:\github\xiangmutest\opencode\zhibangDataBackup
set DATE=%date:~0,4%-%date:~5,2%-%date:~8,2%
set LOG_FILE=%BACKUP_DIR%\logs\%DATE%-uploads.log
set SOURCE=D:\github\xiangmutest\opencode\zhibang\backend\uploads

echo ===================================== >> "%LOG_FILE%"
echo [Uploads Backup] %date% %time% 开始 >> "%LOG_FILE%"
echo ===================================== >> "%LOG_FILE%"

:: 1. robocopy 单向同步（/E 递归 + /R:1 /W:1 失败重试 + /NP 无进度条 + /LOG+ 追加日志）
:: 注意：不用 /MIR（会删目标端），/E 只加不删 → 实现"只增不减"
robocopy "%SOURCE%" "%BACKUP_DIR%\uploads" /E /R:1 /W:1 /NP /BYTES /LOG+:"%LOG_FILE%" >> "%LOG_FILE%" 2>&1
if %errorlevel% lss 8 (
    echo [Uploads Backup] ✅ 同步完成（退出码 %errorlevel%：0=无变化，1=已复制，2=多余文件被删，3=复制+删除等）>> "%LOG_FILE%"
) else (
    echo [Uploads Backup] ❌ 失败 退出码 %errorlevel% >> "%LOG_FILE%"
)

echo [Uploads Backup] 完成 %time% >> "%LOG_FILE%"
echo. >> "%LOG_FILE%"
```

> **robocopy 退出码说明**：0=无变化，1=已复制文件，2=多余文件被删（我们用 /E 不会触发），3=复制+删除。我们只接受 0 或 1。

### 4.3 `backup-master.bat`（主脚本 + 注册任务）

```bat
@echo off
chcp 65001 > nul
title zhibang Nightly Backup Master

set BACKUP_DIR=D:\github\xiangmutest\opencode\zhibangDataBackup
set TASK_NAME=zhibang-nightly-backup

:: 1. 检查备份目录
if not exist "%BACKUP_DIR%" (
    mkdir "%BACKUP_DIR%"
    mkdir "%BACKUP_DIR%\db"
    mkdir "%BACKUP_DIR%\uploads"
    mkdir "%BACKUP_DIR%\logs"
    echo [Master] 创建目录 %BACKUP_DIR% 完成
)

:: 2. 调 db 备份
call "%BACKUP_DIR%\backup-db.bat"

:: 3. 调 uploads 备份
call "%BACKUP_DIR%\backup-uploads.bat"

:: 4. 注册/更新 Windows 任务计划程序
schtasks /query /tn "%TASK_NAME%" >nul 2>&1
if %errorlevel% neq 0 (
    echo [Master] 注册任务计划程序...
    schtasks /create /tn "%TASK_NAME%" /tr "%BACKUP_DIR%\backup-master.bat" /sc daily /st 00:00:00 /ru SYSTEM /rl HIGHEST /f
    if %errorlevel% equ 0 (
        echo [Master] ✅ 任务已注册：%TASK_NAME% 每天 00:00
    ) else (
        echo [Master] ❌ 任务注册失败 退出码 %errorlevel%
    )
) else (
    echo [Master] 任务已存在：%TASK_NAME%
)
```

## 5. 任务计划程序

| 字段 | 值 |
|---|---|
| 任务名 | `zhibang-nightly-backup` |
| 触发器 | 每天 00:00:00 |
| 操作 | `D:\github\xiangmutest\opencode\zhibangDataBackup\backup-master.bat` |
| 运行身份 | `SYSTEM` |
| 最高权限运行 | ✅ |
| 注册方式 | `schtasks /create /tn "zhibang-nightly-backup" /tr "..." /sc daily /st 00:00:00 /ru SYSTEM /rl HIGHEST /f` |
| 自动重新注册 | master.bat 启动时检查，缺失则自动注册（无需手动） |

## 6. 恢复流程

### 6.1 数据库恢复

```bat
:: 停后端
schtasks /run /tn "zhibang-backend"   :: 如有注册
:: 或手动 Ctrl+C

:: 解压
gzip -d D:\github\xiangmutest\opencode\zhibangDataBackup\db\YYYY-MM-DD.dump.gz

:: 恢复（覆盖现有库！）
dropdb -U postgres zhibang
createdb -U postgres zhibang
pg_restore -U postgres -d zhibang D:\github\xiangmutest\opencode\zhibangDataBackup\db\YYYY-MM-DD.dump

:: 启后端
cd D:\github\xiangmutest\opencode\zhibang\backend
npm run start
```

### 6.2 附件恢复

```bat
:: 把备份目录整个拷回（覆盖）
xcopy /E /Y /I D:\github\xiangmutest\opencode\zhibangDataBackup\uploads D:\github\xiangmutest\opencode\zhibang\backend\uploads
```

## 8. 日常维护

- **每日**：自动备份（无需操作）
- **每周**：检查 `D:\github\xiangmutest\opencode\zhibangDataBackup\logs\` 是否有错误
- **每月**：检查 `D:\github\xiangmutest\opencode\zhibangDataBackup\` 目录大小（uploads 持续增长属正常）
- **磁盘预警**：当备份目录 > 50 GB 时考虑扩展磁盘或迁移到外置硬盘

## 9. 故障排查

| 问题 | 原因 | 解决 |
|---|---|---|
| 任务没运行 | 任务计划程序未启动 / 时间不准 | `schtasks /query /tn "zhibang-nightly-backup"` 检查；电脑休眠导致没运行 → 改电源设置为"从不休眠" |
| pg_dump 失败 | PG 未启动 / 密码错 | 检查 PG 服务；检查 `.env` DATABASE_URL |
| robocopy 没复制 | 源端没新文件 / 权限问题 | 看 `logs/YYYY-MM-DD-uploads.log` 详细输出 |
| 备份目录满 | uploads 持续增长 | 迁移到外置硬盘 / 考虑改用 NAS |

## 10. 维护规则（加入 `crm系统说明文件.md`）

> 任何时候改了**数据库结构**（schema.prisma 变更）→ 立即**手动跑一次 `backup-master.bat`**，确保新表结构被备份。
> 任何时候改了**附件上传逻辑**（upload.controller.ts）→ 立即手动跑一次，确认 robocopy 同步正常。
